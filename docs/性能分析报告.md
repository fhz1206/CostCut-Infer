# 性能分析报告（v0.2——最新实测与现状）

> 日期：2026-08-18 ｜ 对象：CostCut Infer（Python 版 + Rust 版）｜ 环境：12GB CPU-only 笔记本（torch 4 线程 BLAS；Rust release）

## 1. 最新实测（token 返回速度，重新实测）

| 版本/规模 | 实测 | 说明 |
|---|---|---|
| **Python 40 层全模型 decode** | **36.08 s/token（0.0277 tok/s）** | 对齐后（KV 预分配+算子融合，早期 61.8——**~42% 提升**） |
| **Python 5 层 decode** | **2.01 s/token（0.498 tok/s）** | 对齐后（早期 ~5.9） |
| **Rust 合成模型 generate** | **~0.07 ms/token** | 1 层小规模（功能验证） |

## 2. 实测数据汇总

### Python 版（liteengine，真实模型 Qwen3.6-35B-A3B-AWQ-4bit）

| 项目 | 实测 | 说明 |

## 3. 理论预估（优化方向的天花板）

| 方向 | 理论提升 | 预估目标 |
|---|---|---|
| Rust BLAS/SIMD matmul（candle/tch 或 AVX2 分块） | 10-50x vs 朴素 | Rust 真实模型规模可达/超过 Python 的 torch 基线 |
| int4/FP8 SIMD 打包内核（T-MAC/llama.cpp 风格） | 1.5-2x（Python）/ 2-3x（Rust） | Python 40 层 → ~15-25 s/token |
| 投机解码（高接受率时） | 1.5-3x | 40 层 → ~12-25 s/token |
| 缓存感知 matmul（Rust 分块） | 3-6x vs 朴素 | — |
| **组合（int4 + 投机 + 融合）** | 2-5x | 40 层理论下限 **~7-15 s/token** |

> 注：理论基于 matmul ~50% 占比 + 内核级实现（朴素融合/手写 AVX2 实测为负——需 SIMD 打包与分块）；
> CPU-only 硬件天花板 ~10-20 tok/s（多核 BLAS + int4 内核）。

## 4. 性能区别分析（按环节）

| 环节 | Python（torch/numpy） | Rust（纯 std） | 核心区别 |
|---|---|---|---|
| matmul | torch BLAS（cache-blocking + SIMD） | 朴素三重循环（无 BLAS/SIMD） | **量级差距**：真实模型规模下 Rust 朴素 matmul 远慢于 BLAS |
| 注意力 | torch eager（4 线程 BLAS） | 每头朴素循环 + 标量 matmul | Python 靠 BLAS；Rust 逐头标量 |
| 专家/MoE | numpy 向量化反量化 + LRU 缓存 + BLAS | 逐元素标量循环 | Python 向量化 vs Rust 标量 |
| 内存模型 | torch 零拷贝切片（KV 预分配受益） | owned Vec（操作即拷贝） | Python 的 KV 预分配/切片收益大 |
| 并行 | torch 4 线程 BLAS（已饱和） | std::thread 并行 matmul（2.56x） | Rust 朴素循环并行收益明显 |
| 精度适配 | torch_dtype 探测 + fp16 保留 + compute_dtype | FP8/NVFP4 转换 + 统一 fp32 计算 | 加载/推理的精度适配已就绪 |
| 语言开销 | 解释器逐层调用 | 编译零开销 | Rust 调度开销低，但被朴素 matmul 掩盖 |

### 核心结论

- **Python 版**：可跑真实模型（36.08 s/token）——瓶颈是 torch fp32 计算内核 + 反量化→matmul 双重内存往返；KV 预分配/算子融合/缓存有效；优化开关（compute_dtype/expert_parallel/int4_fused/speculate）可配置。
- **Rust 版**：纯 std 功能验证——**最大瓶颈是缺少 BLAS/SIMD**（朴素 matmul 真实模型规模会远慢于 torch；手写 AVX2 实测反慢）。
- **两版共同**：int4/FP8 反量化→matmul 双重内存往返——朴素融合/手写内核实测为负，需 SIMD 打包内核。

## 5. 优化方向

### Python 版（按收益排序）

| 方向 | 方法 | 预期 |
|---|---|---|
| int4/FP8 SIMD 打包内核 | T-MAC/llama.cpp Q4 风格（向量化解包 + 融合） | 1.5-2x（真实最大杠杆） |
| 投机解码调优 | 草稿质量/接受率 + 长对话实测（当前默认关） | 高接受率时 1.5-3x |
| 不同精度计算内核 | fp16/bf16 原生 matmul（配合 compute_dtype——当前 CPU 实测 fp32 最优） | 视硬件 |
| 算子融合继续 | norm+投影融合等 | 5-15% |
| KV 预分配（已实施） | 长上下文收益随上下文增长 | 长文场景显著 |

### Rust 版（按收益排序）

| 方向 | 方法 | 预期 |
|---|---|---|
| BLAS/SIMD matmul | candle/tch 依赖（需联网）或 AVX2 分块缓存优化 | 10-50x（核心瓶颈） |
| 真实模型接入 | Qwen3.5 的 delta rule + 量化分离专家 | 让 Rust 可测真实速度 |
| int4/FP8 SIMD 打包内核 | T-MAC 风格（朴素融合实测负收益的出路） | 2-3x |
| 并行扩展 | matmul_par 已有 2.56x——扩展到注意力/MoE | 2-3x |

## 6. 结论

1. 两版定位不同：Python 版面向真实推理（torch BLAS）；Rust 版为纯 std 功能验证（真实模型规模需先解决 BLAS/SIMD）。
2. 共同瓶颈：int4/FP8 反量化→matmul 双重内存往返——需 SIMD 打包内核（朴素融合/手写 AVX2 实测均负）。
3. 精度适配（不同精度模型：fp32/fp16/bf16/fp8/int4）与优化开关（engine.toml）已就绪——为多精度模型与他机调优提供基础。
