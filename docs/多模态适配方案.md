# 多模态适配方案（评估 + 注册点设计）

> 日期：2026-08-18 ｜ 对象：CostCut Infer（Python 版）
> 现状评估：**多模态当前为 0**（无任何视觉代码）；本机 CPU-only、无视觉推理依赖与多模态模型。

## 1. 现状评估（诚实）

| 项 | 状态 |
|---|---|
| 视觉代码 | **无**（全仓无 vision/image/pixel 相关实现） |
| 依赖 | 缺视觉编码器依赖（torchvision 等）与多模态模型权重 |
| 硬件 | CPU-only（视觉编码器 ViT 在 CPU 上开销大） |
| 可落地范围 | **注册点与数据流设计**（真实视觉推理需依赖 + 模型 + 端到端验证） |

## 2. 目标架构（数据流）

```
图像输入 ──▶ 图像预处理（resize/归一化/分块）
                │
                ▼
        视觉编码器（ViT/SigLIP 等——registry 注册）──▶ 视觉 token 嵌入 (n, D)
                │
                ▼
        投影层（mlp/linear——映射到文本隐藏维）
                │
                ▼
        与文本嵌入按序列拼接 ──▶ 引擎前向（现有 DecoderLayer 不变）
```

- 多模态模型的 config 探测：`vision_config`（图像侧）+ `text_config`（文本侧）——参照 Kimi-VL/GLM-4V/DeepSeek-VL
- 视觉 token 与文本 token 的序列拼接 + 位置编码处理（图像分块的行列位置）

## 3. 注册点设计（已实现——registry.py）

| 接口 | 说明 |
|---|---|
| `register_vision_encoder(name)` | 注册视觉编码器（装饰器） |
| `get_vision_encoder(name)` | 按名称取编码器（未注册返回 None） |
| `list_vision_encoders()` | 已注册列表 |

扩展方式（与现有四注册点一致）：外部实现编码器后装饰器注册即可接入，不修改核心代码。

## 4. 接入流程（后续实现）

1. `load_model_config` 增加多模态字段（`vision_config` / 图像 token 数）
2. 视觉编码器实现（ViT 前向——图像 → 视觉嵌入）——`register_vision_encoder` 注册
3. 投影层 + 序列拼接（`liteengine/vision/` 子包）
4. 端到端验证（多模态模型推理——依赖 + 权重就绪后）

## 5. 后续依赖

- 视觉编码器依赖（torchvision 或 transformers 的 ViT/SigLIP）
