# 性能分析报告（v0.3——当前状态）

> 日期：2026-08-18 ｜ 对象：CostCut Infer（Python 版 + Rust 版）｜ 环境：12GB CPU-only 笔记本（torch 4 线程 BLAS；Rust release）

## 1. 最新实测（token 返回速度）

| 版本/规模 | 实测 | 说明 |
|---|---|---|
| **Python 40 层全模型 decode** | **36.08 s/token（0.0277 tok/s）** | 对齐后（KV 预分配+算子融合，早期 61.8——**~42% 提升**） |
| **Python 5 层 decode** | **2.01 s/token（0.498 tok/s）** | 对齐后（早期 ~5.9） |
| **Python 5 层长上下文（4096-token）decode** | **2.12 s/token** | 注意力 O(ctx) 主导 + KV 预分配无每步 concat |
| **Rust 合成模型 generate** | **~1.0 ms/3 token（依赖启用后）** | 1 层小规模（功能验证——KV 缓存续接生成；依赖启用后无退化——详见 Rust版本性能测试报告.md） |

## 2. 实测数据汇总

| 项目 | 实测 | 说明 |

| 项目 | 实测 | 说明 |

## 3. 理论预估（优化方向的天花板）

| 方向 | 理论提升 | 预估目标 |
|---|---|---|
| Rust BLAS/SIMD matmul（candle/tch 或 AVX2 分块向量化） | 10-50x vs 朴素 | Rust 真实模型规模可达/超过 Python 的 torch 基线 |
| int4/FP8 SIMD 打包内核（T-MAC/llama.cpp 风格） | 1.5-2x（Python）/ 2-3x（Rust） | Python 40 层 → ~15-25 s/token |
| 投机解码（高接受率时） | 1.5-3x | 40 层 → ~12-25 s/token |
| 缓存感知 matmul（Rust 分块 + SIMD） | 3-6x vs 朴素 | 需与向量化结合 |
| **组合（int4 + 投机 + 融合）** | 2-5x | 40 层理论下限 **~7-15 s/token** |

> 注：理论基于 matmul ~50% 占比 + 内核级实现（朴素融合/手写 AVX2/标量分块实测均负——需 SIMD 打包与向量化分块）；CPU-only 硬件天花板 ~10-20 tok/s。

## 4. 性能区别分析（按环节）

| 环节 | Python（torch/numpy） | Rust（纯 std） | 核心区别 |
|---|---|---|---|
| matmul | torch BLAS（cache-blocking + SIMD） | 朴素三重循环（无 BLAS/SIMD） | **量级差距**：真实模型规模下 Rust 朴素 matmul 远慢于 BLAS |
| 注意力 | torch eager（4 线程 BLAS） | 每头朴素循环 + 标量 matmul | Python 靠 BLAS；Rust 逐头标量 |
| 专家/MoE | numpy 向量化反量化 + LRU 缓存 + BLAS | 逐元素标量循环 | Python 向量化 vs Rust 标量 |
| delta rule | torch chunk/recurrent | Rust chunk/recurrent（等价 0.0018 残余） | 已同步（数学等价基本达成） |
| 内存模型 | torch 零拷贝切片（KV 预分配受益） | owned Vec（操作即拷贝） | Python 的 KV 预分配/切片收益大 |
| 并行 | torch 4 线程 BLAS（已饱和） | std::thread 并行 matmul（2.56x） | Rust 朴素循环并行收益明显 |
| 分发/扩展 | 插件注册表（五注册点） | Attention trait 注册表（已同步） | Rust 的注册表化对齐 Python |
| 精度适配 | torch_dtype + fp16 保留 + compute_dtype | f32-only（fp16 内核归 P2） | 加载适配就绪；Rust 计算内核为后续 |

### 核心结论

- **Python 版**：可跑真实模型（36.08 s/token）——瓶颈是 torch fp32 计算内核 + 反量化→matmul 双重内存往返；优化开关（compute_dtype/expert_parallel/int4_fused/speculate）可配置。
- **Rust 版**：纯 std 功能验证——**最大瓶颈是缺少 BLAS/SIMD**（朴素 matmul 真实模型规模会远慢于 torch；手写 AVX2/标量分块实测均负）。
- **两版共同**：int4/FP8 反量化→matmul 双重内存往返——朴素融合/手写内核/标量分块实测为负，需 SIMD 打包内核。

## 5. 精度适配与优化开关

- **不同精度覆盖**：fp32 / fp16 / bf16 / FP8（E4M3/E5M2）/ NVFP4（E2M1）/ int4（AWQ）——加载与推理适配就绪
- **优化开关**（engine.toml `[inference]`）：`compute_dtype`（fp32 默认/fp16/bf16）、`expert_parallel`、`int4_fused_matmul`、`speculate`——本机实测负收益项默认关，他机可试
- **投机解码**：dspark（markov_head）+ MTP 模块 + DFlash 骨干确认（5 层实测慢——开关化）

## 6. 优化方向

### Python 版（按收益排序）

| 方向 | 方法 | 预期 |
|---|---|---|
| int4/FP8 SIMD 打包内核 | T-MAC/llama.cpp Q4 风格（向量化解包 + 融合） | 1.5-2x（真实最大杠杆） |
| 投机解码调优 | 草稿质量/接受率 + 长对话实测（当前默认关） | 高接受率时 1.5-3x |
| 不同精度计算内核 | fp16/bf16 原生 matmul（配合 compute_dtype） | 视硬件 |
| 算子融合继续 | norm+投影融合等 | 5-15% |
| KV 预分配长上下文 | 已实施——继续验证长文收益 | 长文场景显著 |

### Rust 版（按收益排序）

| 方向 | 方法 | 预期 |
|---|---|---|
| BLAS/SIMD matmul | candle/tch 依赖（需联网）或 AVX2 向量化分块 | 10-50x（核心瓶颈） |
| 真实模型接入 | Qwen3.5 的 delta rule 完整类（conv/投影/forward）+ 量化分离专家组装 | 让 Rust 可测真实速度 |
| int4/FP8 SIMD 打包内核 | T-MAC 风格（朴素融合/分块实测负收益的出路） | 2-3x |
| 并行扩展 | matmul_par 已有 2.56x——扩展到注意力/MoE | 2-3x |

## 7. 结论

1. 两版定位不同：Python 版面向真实推理（torch BLAS）；Rust 版为既有功能的性能优化路径（新功能 Python 首发——见同步清单）。
2. 共同瓶颈：int4/FP8 反量化→matmul 双重内存往返——需 SIMD 打包内核（朴素融合/手写 AVX2/标量分块实测均负）。
3. 精度适配（不同精度模型）与优化开关（engine.toml）已就绪；未来方向详见 `docs/total/未来性能开发方向报告.md`（进度状态已更新）。
