# 未来性能开发方向报告

> 日期：2026-08-18 ｜ 对象：CostCut Infer（Python 版 + Rust 版）
> 基线：Python 40 层 36.08 s/token（0.0277 tok/s）；Rust 合成模型 ~0.07 ms/token（纯 std）
> 原则：**实测驱动**——朴素融合/手写 AVX2/专家并行实测均为负收益，每项方向须先做内核级实现再实测，避免重复负收益。

## 1. 当前瓶颈

| 版本 | 瓶颈 | 说明 |
|---|---|---|
| Python | torch fp32 计算内核 + 反量化→matmul 双重内存往返 | 40 层 36.08 s/token；KV 预分配/算子融合已受益 |
| Rust | 无 BLAS/SIMD（朴素 matmul） | 真实模型规模（2048³ 级）会远慢于 torch；手写 AVX2 实测反慢（0.69x） |
| 共同 | int4/FP8 反量化→matmul 双重往返 | 朴素融合实测慢 2.7 倍——需 SIMD 打包内核 |

## 2. 方向清单（按收益 / 可行性分层）

### A. int4/FP8 SIMD 打包内核（P0——Python + Rust 共同最高杠杆）

- **方法**：T-MAC / llama.cpp Q4 风格——**向量化解包**（一次加载 16 个 4-bit 值 → SIMD 寄存器解包）+ 解量化融合进 matmul（避免反量化结果的写回-重读往返）+ int8/FP8 中间计算
- **预期**：1.5-2x（Python）/ 2-3x（Rust）
- **现状**：朴素融合（逐元素位解包）实测慢 2.7 倍——正是需要 SIMD 打包的原因；`int4_fused_matmul` 开关已预留
- **验证**：真实模型 decode 计时对比（40 层 s/token vs 36.08 基线）；反量化路径 max_abs 误差 < 1e-3

### B. Rust BLAS/SIMD matmul（P0——Rust 真实模型规模的核心瓶颈）

- **方法**：引入 candle/tch 依赖（需联网——与纯 std 离线约束冲突，需权衡/双路径）或 std::arch AVX2 **分块缓存优化**（i-k-j 循环 + 8×8 分块 + cache blocking——手写单循环实测 0.69x 反慢，分块是出路）
- **预期**：10-50x vs 朴素
- **验证**：512³ matmul 计时（基线 serial ~20ms）；真实模型 decode

### C. Rust 真实模型接入（P0——B/A 的验证前提）

- **方法**：Qwen3.5 的 delta rule（GatedDeltaNet——chunk/recurrent）移植 + 量化分离专家（AWQ 反量化已就绪）+ 真实权重加载（safetensors 已就绪）
- **预期**：让 Rust 可测真实速度（当前仅合成小模型）
- **现状**：标准注意力/MoE/FP8/NVFP4 已就绪；缺 delta rule 与真实模型组装

### D. 投机解码调优（P1——Python）

- **方法**：草稿质量/接受率优化（spec_states 中间隐藏态 + confidence_head 提前终止）+ 长对话实测
- **预期**：接受率高时 1.5-3x
- **现状**：5 层实测 K=8 0.31x / K=4 0.50x（慢于自回归——验证开销 > 省下 decode）；`speculate` 开关已预留
- **验证**：真实模型长对话接受率与端到端 tok/s

### E. 不同精度计算内核（P1——多精度模型基础）

- **方法**：fp16/bf16 原生 matmul（配合 `compute_dtype`——当前 CPU 实测 fp32 最优，但 ARM / GPU / 其它硬件可试）
- **预期**：视硬件（本机负收益已记录）
- **现状**：torch_dtype 探测 + fp16 原 dtype 保留 + compute_dtype 配置已就绪——内核级 fp16 matmul 未实现
- **验证**：compute_dtype=fp16 的 decode 计时 vs fp32 基线

### F. V4-Flash / DSA 索引器（P1——长上下文稀疏注意力）

- **方法**：DeepSeek-V4 的压缩注意力（compressor + index heads）+ GLM-5 的 DSA（index_topk/index_head_dim——稀疏注意力）——字段已解析
- **预期**：长上下文收益（稀疏注意力 O(1) 记忆）
- **现状**：经典 MLA 已实现；索引器/压缩注意力未实现（内核级工作）
- **验证**：长上下文（8k+）decode 计时 vs 经典 MLA

### G. KV 预分配长上下文（P1——已实施，继续验证）

- **方法**：长上下文（8k-32k）下的 decode 计时对比（预分配 vs 早期 concat）
- **预期**：长文场景显著（O(ctx) 每步复制的消除）
- **现状**：已实施（一致性验证通过）；长上下文端到端收益未实测

### H. 算子融合继续（P2——Python）

- **方法**：norm+投影融合（输入 norm 直接喂 q/k/v 投影）、residual+norm 更多点位
- **预期**：5-15%
- **现状**：rms_norm_add 已实施（40 层提速 ~42% 的组成部分）

## 3. 优先级与预估收益

| 优先级 | 方向 | 预估收益 | 依赖 |
|---|---|---|---|
| **P0** | A. int4/FP8 SIMD 打包内核 | 1.5-2x（Py）/ 2-3x（Rust） | 无 |
| **P0** | B. Rust BLAS/SIMD matmul | 10-50x | 联网依赖或分块实现 |
| **P0** | C. Rust 真实模型接入 | 可测真实速度 | delta rule 移植 |
| P1 | D. 投机解码调优 | 1.5-3x | 长对话实测 |
| P1 | E. 不同精度计算内核 | 视硬件 | 内核实现 |
| P1 | F. V4-Flash / DSA 索引器 | 长上下文收益 | 内核实现 |
| P1 | G. KV 预分配长上下文验证 | 长文显著 | 无（已实施） |
| P2 | H. 算子融合继续 | 5-15% | 无 |

## 4. 建议执行顺序

1. **A（int4 SIMD 打包内核）**——Python 与 Rust 共同最大杠杆，收益确定（理论 1.5-2x）
2. **C（Rust 真实模型接入）→ B（Rust BLAS/SIMD）**——先让 Rust 可测真实速度，再优化 matmul 内核
3. **D（投机调优）+ G（长上下文验证）**——Python 侧端到端收益
4. **F（V4-Flash/DSA）**——长上下文路线
5. **E（不同精度内核）+ H（融合继续）**——收尾

> 每项方向落地时须先实现内核级版本再实测对比基线，避免重复朴素实现的负收益（int4 融合 / 手写 AVX2 / 专家并行均为先例）。
