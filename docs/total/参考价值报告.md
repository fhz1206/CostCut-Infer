# AirLLM / llama.cpp / vLLM 对当前开发工作的参考价值报告

> 日期：2026-08-22 ｜ 对象：CostCut Infer（Python liteengine + Rust costcut-infer——12GB CPU-only 笔记本）
> 范围：三个开源项目的核心技术对当前开发（CPU 推理引擎 + MoE 量化模型）的参考价值评估——已参考/未参考 + 优先级。

## 1. AirLLM（本地克隆——layer-wise offload）

| 核心技术 | 原理 | 对当前开发的价值 | 状态 | 优先级 |
|---|---|---|---|---|
| **层级逐层 offload** | forward hooks 逐模块加载/释放权重 + prefetching（worker 线程预取下一模块） | 降内存峰值（（层数从 config.json 读取） × （专家数从 config.json 读取）可驻留内存有限） | **已参考**（Python `layer_offload`——层前向后释放专家缓存） | ✅ 已实施 |
| **内存上限控制**（max_pinned_layer_bytes） | 单层预取内存上限——防止 OOM | Rust 从 real 构造可借鉴（防 （层数从 config.json 读取）全量驻留） | 未参考 | **P1** |
| **磁盘分片缓存**（disk shard cache） | 层权重分片落盘——按需读入 | 大模型换层加载（真实端到端内存优化） | 未参考 | P2 |
| 分块量化（block-wise quant） | 块级反量化加速 | 本项目用 AWQ（等价思路已内建） | 已参考（AWQ） | ✅ |

**参考价值**：结构层最高（层级 offload 已落地）——剩余价值在内存上限控制（P1）与磁盘分片缓存（P2）。


## 2. vLLM（PagedAttention / continuous batching）

| 核心技术 | 原理 | 对当前开发的价值 | 状态 | 优先级 |
|---|---|---|---|---|
| **PagedAttention** | KV 缓存分页管理——按需分配/复用 | KV 内存优化（长上下文 （层数从 config.json 读取） × 多轮） | 未参考（KV 缓存为简单实现） | P2 |
| **continuous batching** | 多请求连续批处理 | 单用户场景价值有限 | 未参考 | P3 |
| **prefix caching** | 前缀 KV 缓存复用 | 多轮对话/投机解码加速 | 未参考 | P2 |
| 量化内核 | 各量化格式的高效内核 | 与 llama.cpp 的 SIMD 思路重叠 | 未参考 | P2 |

**参考价值**：服务层（多用户吞吐）——对单机 CPU 推理价值有限；PagedAttention/prefix caching 为 P2。

## 3. 优先级汇总

| 优先级 | 参考项 | 来源 | 解决什么 |
|---|---|---|---|
| **P1** | 内存上限控制（max_pinned_layer_bytes） | AirLLM | from_real 构造 （层数从 config.json 读取）的内存保护 |
| **P2** | mmap 内存映射 ｜ 磁盘分片缓存 ｜ PagedAttention ｜ prefix caching | llama.cpp / AirLLM / vLLM | 加载内存/长上下文 KV 优化 |
| **P3** | continuous batching | vLLM | 多用户吞吐（单机价值低） |

## 4. 结论
1. **AirLLM 结构价值已兑现**：层级 offload 已实施 ✓——剩余 P1（内存上限）轻量可补。
2. **vLLM 服务层价值**：对单机 CPU 推理价值有限——PagedAttention/prefix caching 为 P2 深水区。
3. 当前最紧迫：参考 llama.cpp 的 SIMD 打包内核解决层前向挂起——这是达成 7-8 tokens/s 的核心路径。
